# Architecture

*[Português](architecture.pt-BR.md)*

```text
src/simple_phone/
  _native/      PJSUA2 SWIG binding (generated by scripts/build_pjsip.sh, compiled by setup.py)
  core/         PJSUA2 on one thread: Engine, Endpoint, Account, Call, AMD, SIP trace parsing
  events.py     typed events: CallEvents and PhoneEvents
  models.py     Settings, Limits, Timeouts, errors, Report/Stats/Amd
  phone.py      AsyncPhone and the hub that routes core events to phones and calls
  call.py       Call: actions, waits, streams
  sync.py       Phone: AsyncPhone without await, on a loop in its own thread
  media.py      audio frames, streams, STT/TTS (Whisper, Piper)
  cli.py        the simple-phone command
```

Each layer imports only the layers below it: `core` knows nothing about asyncio, `phone.py` and `call.py` know nothing about the CLI.

## Threads

PJSUA2 runs with `mainThreadOnly`. One engine thread (`core/engine.py`) creates the library, runs `libHandleEvents()` and executes every command. Other threads never call PJSUA2.

- **Commands:** `engine.submit(function, *args)` returns a `Future`. `AsyncPhone._run` wraps it for asyncio, and `pj.Error` becomes `PhoneError`.
- **Events:** the core builds typed events (`events.py`) and gives them to the engine's listeners on the engine thread. The hub (`_Hub` in `phone.py`) hands each event to the event loop with `call_soon_threadsafe`.
- **Media callbacks** (`onFrameReceived`, `onFrameRequested`) run on a PJMEDIA thread. They touch only Python buffers, never PJSUA2, and never raise into C++.

## Routing

Every event carries `account_id`, `ref` (the call's own id) and `call_id` (the SIP Call-ID). The hub:

- Finds the `AsyncPhone` by `account_id` and the `Call` by `ref`. Then it fills `event.phone` and `event.call` with `dataclasses.replace`.
- Registers an outgoing `Call` (`acquire`) before the core dials, so the first events already have a destination.
- Keeps the SIP messages of an incoming INVITE (`early`) until PJSUA creates its call.
- Keeps the last 100 ended calls (`ended`) for the BYE and 200 that are logged after DISCONNECTED.

The SIP trace comes from the PJSIP log (level 4). `LogWriter` parses each message (`core/sip.py`) and `Endpoint.sip_identity` decides which account and call it belongs to. The same parser reads BLF state from dialog-event NOTIFYs, because PJSUA2 does not expose dialog-info.

## Object lifetimes

Breaking any of these crashes the process:

- **A call's PJSUA2 object** is dropped inside its DISCONNECTED callback (`Endpoint.finish`). Deleting it later lets `~Call` clear the slot that a new call may already reuse. The API never holds native objects: `Call._do` looks the core call up by `ref` on the engine thread.
- **REFER and Replaces** need a new `Call` object for the new call (`Endpoint.child_call`). Otherwise two calls share one object, and deleting it leaves a dangling pointer.
- **Python-backed ports and buddies** are deleted explicitly (`destroy_native`) while their Python object is alive. Ports can be inside a media callback. `Account.shutdown()` would delete a `Buddy` a second time.
- **`info = call.getInfo()`** must stay in a variable while `info.media` is used.

## Building

`scripts/build_pjsip.sh` builds PJSIP 2.17 as static PIC libraries, with the limits in `packaging/config_site.h` (64 calls, players and recorders), without video and without TLS by default. It then generates the SWIG wrapper into `_native/`. `setup.py` compiles that wrapper and links it against the static libraries, so the wheel needs nothing from the system except `libasound.so.2`.
